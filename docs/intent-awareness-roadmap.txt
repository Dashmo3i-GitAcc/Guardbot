  time (only re / unicodedata / dataclasses) and a test asserts the import set.
* `awareness_context` stays the ONLY importer of the readers; it may import
  nothing that could send/delete/restrict/ask a model (asserted structurally).
  It is imported by app/main.py and by the gated voice_live bridge.

  this branch is in the foundation, before the lettering: commit `151b1e1`

  `_ensure_column`, so a row written before it reads as ''/0 and code from before

  DESIGN (measured on this host before a line of W was written)
  ------------------------------------------------------------------------------
  THE EXISTING ARCHITECTURE CANNOT CARRY IT. Inspected first, as the stop rule
  requires: ``people`` is per-room identity metadata and a message COUNT — it has
  no column for a fact and its docstring makes that a refusal; ``identities`` is
  an opaque per-user uuid; ``awareness_state`` is a one-row-per-chat derived
  cache of the room, not of a person; ``chat_messages`` is the assistant's own
  conversation with one person. None of them stores a durable fact about a
  person. So a new table is genuinely necessary, and it is the first genuinely
  necessary one on the branch (T's turned out to be derivable).

  THE BOUNDED MODEL, FROM THE BENCHMARK (not from the brief's 20–50). Two
  synthetic runs at the owner's scale (3000 members, 120-character values, WAL):
    * storage: 208 bytes/row; 30 items/user x 3000 users = 17.9 MB, 50 = 29.8 MB,
      100 = 59.5 MB — every one of them an order of magnitude under the 200 MB
      ceiling, so DISK IS NOT THE BINDING CONSTRAINT and must not choose the cap.
    * write: one upsert = 0.50 ms p50 / 0.70 ms p95 (commit-dominated);
    * per-user prune-to-cap = 0.021 ms p50; retrieval of one person's items =
      0.033 ms p50 / 0.13 ms p95.
    * a whole-table ``NOT IN`` prune over 90k rows is the one expensive statement
      — measured at **266 ms**, roughly three orders of magnitude above the
      indexed per-user delete — so the global cap is enforced rarely and the
      hot-path prune is the indexed per-user one. (The age delete is indexed and
      cheap: 0.19 ms with no rows to remove.)
  What the cap actually bounds is therefore the *quality property*, not cost: a
  memory is only useful if the relevant item can be surfaced, and retrieval into
  a ~300-character block can surface at most ~4 items. So the cap is set with
  margin over what can ever be read: ``NEXUS_MEMORY_MAX_PER_USER = 30`` (inside
  the brief's range, chosen by measurement rather than copied), which gives a
  ~7x recall margin over the block and keeps the table a bounded FACT SET rather
  than a log. ``NEXUS_MEMORY_MAX = 50000`` rows globally and
  ``NEXUS_MEMORY_RETENTION = 180 days``, both applied on the observation path
  (this process has no scheduler) every ``PRUNE_EVERY`` recordings, exactly as
  ``people`` does.

  SCHEMA (additive, new table — the 151b1e1 precedent is "additive, never
  destructive"; a new table needs no ``_ensure_column`` and touches no existing
  row):
      user_memory(chat_id, user_id, key, category, value, source, confidence,
                  created_at, updated_at, used_at)  PRIMARY KEY (chat_id,user_id,key)
      INDEX (chat_id, user_id, updated_at)   -- retrieval and the per-user prune
      INDEX (updated_at)                     -- the age prune
  Rollback: ``DROP TABLE user_memory``. No existing table is altered, no row
  outside it is touched, and code from before the change never reads it.

  EXTRACTION IS EXPLICIT-ONLY, AND COSTS NO CALL. The evidence rule forbids a
  model call on the ordinary path, and deterministic free-text-to-fact parsing is
  exactly the kind of guessing this codebase refuses. So W v1 writes ONLY from an
  explicit, user-authored request to be remembered, matched by a narrow trigger
  detector in the same "evidence, never authority" shape as ``requests``/``objects``
  (the clause the person typed is stored, bounded and verbatim, and never a fact
  the server inferred). Semantic extraction from ordinary conversation — which
  would need a model call or a change to the awareness prompt — is deliberately
  NOT built; it is recorded as a later, separately-evidenced increment.

  RETRIEVAL IS RELEVANCE-BASED AND KEYED ON THE SUBJECT. The block renders the
  memories of the person the batch is ABOUT (``ctx.anchor_id()``), never of the
  speaker merely because they spoke, and never the room's. ``(chat_id, user_id)``
  is the key, so a group cannot inherit another group's memory and a private-chat
  memory cannot render in a group — isolation is by construction, not by a check.
  It is one more ``Source`` in ``awareness_context.SOURCES``, bounded to
  ``NEXUS_MEMORY_ITEMS`` items and ``NEXUS_MEMORY_CHARS`` characters, and it is a
  READER like every other: it reports what was recorded, it grants nothing, and
  it is never an input to a permission decision.

  RESULT
  ------------------------------------------------------------------------------
  DONE, and it is the branch's first genuinely necessary table. Built as one
  additive new table (``user_memory``) with two indexes, a new reader/writer
  module (``app/memory.py``) in the "evidence, never authority" shape, one new
  ``Source`` in the registry, and the write hooked into the observation path
  beside ``people.remember``. NO existing table was altered, so rollback is
  ``DROP TABLE user_memory``.
  Measured (``tools/eval_memory.py``, deterministic and offline):
    * extraction — 12 positives / 13 negatives, precision **1.0**, recall
      **1.0**, **0** false positives. The negatives include the two that matter:
      an ordinary «من ادمینم» and a request to remember an ACTION.
    * storage — **202 bytes/row** through the real write path. The pre-build
      sizing predicted 208 / 17.9 MB; the build measured 202 and the model held.
      **3000 members x 30 items = 17.4 MB**, an order of magnitude under the
      200 MB budget. Disk never chose the cap; the ~4 items the block can surface
      did. (The benchmark's own table stopped at 50000 rows — the global bound
      firing on itself, which is the bound working rather than a measurement
      error.)
    * write — the upsert plus the indexed per-person prune, **0.22 ms p50 /
      0.62 ms p95**.
    * retrieval — the context block's read, **0.005 ms p50 / 0.02 ms p95**.
    * the block — bounded to ``NEXUS_MEMORY_CHARS`` including its framing line;
      mean 36 / max 145 characters over the sample.
    * Gemini/provider calls — **0**. ``memory`` imports no model client, and the
      write is a regex over text the handler already holds.
  Corpus (``tools/eval_intent.py`` over 141 cases): ``user_memory`` renders on

  The assembled context moved mean 954 → **1046** / max 1498 → **1489** (still

  Tests: 3266 → **3314** (+47 in ``tests/test_memory.py``, +1 in

6. END STATE — WHAT "COMPLETE" MEANS FOR THIS PROJECT
--------------------------------------------------------------------------------
Grounded in the actual architecture, not in ambition. The evolution is complete
when ALL of the following hold:

 1. THE DETERMINISTIC LAYER IS COMPLETE AND SCORED. Every reader (addressing,
    referents, discourse, temporal, room_state, entities, requests, objects)
    reports its reading as evidence, never a decision, pure at import time, and
    every sentence the prompt renders from them is scored against the reader's
    own finding — with a non-vacuity proof for each check. No block may order
    the model about a fact its reader does not hold.

 2. THE BENCHMARK IS THE ARBITER. tools/eval_intent.py over a labelled corpus
    is clean: top-1 accuracy, ambiguity recall and precision, wrong-but-
    confident == 0, act claimed precision and false positives == 0, object exact,
    edges exact, every should-be-zero metric at zero, and every floor asserted
    in tests/test_intent_eval.py. The corpus grows by one case per newly
    defensible reading; floors move on purpose by editing the corpus.

 3. THE PROMPT IS BOUNDED AND HONEST. The assembled context stays under the
    1500-character ceiling with per-source budgets; every source that can render
    does render in the benchmark (or is excluded by name and justified); the
    calendar renders first; nothing claims more than its reader found.

 4. THE PASS REMEMBERS WHAT IT READ (T). The readers' output survives the pass
    in a bounded, additive, rollback-safe form, so the server can answer "what
    did I read in that message?" without re-deriving it — and the model's
    structured understanding (intent, about) and the server's deterministic
    reading are joined rather than merely printed beside each other.

 5. SCHEDULING SPENDS THE RATIONED CURRENCY WELL (U). Within the SAME 200
    requests, the pass goes to the rooms that most warrant it, using evidence —
    without violating "awareness.due cannot see messages", without starving any
    room, and without adding a model call.

 6. EVERY BOUNDARY IN §1.3 AND AgentMD §53.7 STILL HOLDS. Readers are evidence;
    awareness_context is the only importer; Intent and Awareness are not
    authority; no message content in logs; OFF means off on every path; the
    window stays bounded; identity comes from the Telegram id and nothing else;
    Gemini workload isolation intact; cross-user/cross-group/cross-private
    isolation intact.

 7. IT IS VERIFIED ON THE RUNTIME, NOT ONLY IN TESTS. Every runtime-path
    increment (T, U, and anything after) has a self-cleaning live end-to-end
    probe with before/after numbers, per the owner's standing preference.

 8. main IS INTACT AND THE BRANCH IS INDEPENDENT. The rollback base
    00c5d1dd412e033c6ac15599b28bc0fbcb54d709 is untouched AND is an ancestor of
    the branch (verified with `git merge-base --is-ancestor`), so the whole
    evolution reverts by leaving the branch unmerged; every increment is also
    individually revertable; nothing is merged or deployed without the owner's
    explicit instruction.

Explicitly NOT part of "complete": dropping to a smaller model, adding keyword
detectors, replying to everything, trading a security property for coverage,
running concurrent passes, unbounded history, or any change to model routing
that is not proven by a measurement.
